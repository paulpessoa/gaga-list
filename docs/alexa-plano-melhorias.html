Skill Alexa do Gaga List: plano de melhorias

Baseado em app/api/alexa/route.ts, app/api/alexa/token/route.ts, app/alexa/link/page.tsx e nos docs da main (28/09/2026).

1. Como funciona hoje

A arquitetura "1 intent + LLM" é boa: mantém o modelo de interação pequeno e deixa a inteligência no código. A ideia é manter o desenho e corrigir as bordas.

2. Diagnóstico por prioridade

CRÍTICOVazamento do refresh token no vínculo de conta

/alexa/link aceita qualquer redirect_uri e manda o refresh token (só em base64) para ela. Um link malicioso como /alexa/link?redirect_uri=https://site-do-atacante&state=x, clicado por alguém logado que aperte "Autorizar", entrega a sessão da conta ao atacante. O /api/alexa/token também não confere client_id/client_secret.

Correção: aceitar só os redirect URLs da Amazon (lista em env); o code passa a ser um valor aleatório de uso único, que expira em 5 min e fica salvo numa tabela alexa_auth_codes; o endpoint de token valida o client secret via HTTP Basic.

CRÍTICOAlexa e navegador compartilham a mesma sessão

O vínculo reaproveita o refresh token da sessão do navegador. O Supabase rotaciona refresh tokens: quando um dos dois (web ou Alexa) renova primeiro, o token do outro fica inválido. Se o reuso for detectado, a sessão inteira pode ser revogada. O sintoma é a Alexa "desvincular sozinha" ou o app web deslogar.

Correção: criar uma sessão dedicada para a Alexa no servidor (admin.generateLink + verifyOtp, ou login com persistSession:false). Assim cada lado tem o próprio token.

CRÍTICO"Anotar leite" sem citar a lista quebra

Sem listName, o insert vai com list_id = null (a coluna é NOT NULL), estoura erro e a Alexa responde "curto circuito". É o comando mais comum.

Correção: ordem de fallback: lista citada, depois a última lista usada na sessão, depois a lista mais recente (ou a única). A resposta diz onde anotou: "Anotei leite no Mercado."

ALTORequisitos de certificação da Amazon
  • Verificar assinatura e timestamp da requisição (SignatureCertChainUrl/Signature-256) e o applicationId = ALEXA_SKILL_ID. Isso é obrigatório para endpoint próprio; sem essa checagem a skill é reprovada na certificação.
  • Reprompt em toda resposta com a sessão aberta (hoje não tem).
  • Card LinkAccount quando não houver token ou ele expirar (hoje só fala um texto).
  • Tratar AMAZON.HelpIntent e AMAZON.FallbackIntent.
ALTOA Alexa pode "mentir" sobre o que fez

O naturalResponse é gerado pelo LLM antes de tocar no banco. Em ADD/CHECK/UPDATE ele é falado mesmo que nada tenha sido salvo (ex.: CALCULATE_TOTAL sem lista cai no fallback e o LLM pode inventar um valor).

Correção: o LLM só interpreta; as frases saem de templates baseados no resultado real. Tirar o campo naturalResponse também diminui tokens e latência.

ALTOLogs com token de acesso

console.log("Alexa Request:", body) grava o accessToken nos logs da Vercel. Logar só request.type, o nome do intent e o requestId.

MÉDIOBusca de listas e itens frágil
  • ilike(title, 'mercado') + .single(): "mercado" não encontra "Mercado do Mês", e dá erro se houver 2 resultados.
  • Filtra owner_id, então listas compartilhadas ficam de fora; também não filtra deleted_at.
  • Melhor e barato: mandar os títulos das listas do usuário no prompt. O LLM devolve o título exato, sem precisar de busca fuzzy no banco.
MÉDIOExperiência de voz
  • Vários itens numa frase: "anotar leite, pão e ovos" hoje vira 1 item só. O schema pode passar a ter items: [{name, quantity, unit}].
  • One-shot encerra: se a sessão começou com o comando ("Alexa, pede pro gaga list anotar leite"), executa e fecha. O "Algo mais?" fica só quando o usuário abriu a skill.
  • Listas longas: ler até 8 itens e completar com "e mais 12. Quer ouvir o resto?".
  • Dinheiro em pt-BR: "12 reais e 50 centavos" em vez de "12.50 reais".
  • Desfazer de verdade: guardar a última operação em sessionAttributes ({op, itemId, snapshot}) e reverter. É um recurso pequeno e poupa o usuário quando a Alexa entende errado.
  • Criar lista nova só depois de confirmar ("Não achei a lista Mercados. Crio?"), para evitar listas duplicadas por erro de transcrição.
MÉDIOLatência e custo
  • Rodar getUser e a busca de listas em paralelo (Promise.all) e só depois chamar o LLM.
  • max_tokens baixo + temperature: 0. O gpt-4o-mini continua uma boa escolha pelo custo.
  • O token/route.ts usa Buffer com runtime = 'edge', onde o Buffer não é garantido. Trocar para nodejs.

5. Ordem de execução sugerida

Fase 1Segurança (antes de qualquer beta)
  1. Allowlist de redirect_uri + validar client_id
  2. Tabela alexa_auth_codes + sessão dedicada
  3. Token route: Basic auth, runtime nodejs
  4. Verificar assinatura + skill ID
  5. Parar de logar o token

Depois: re-vincular a conta no app Alexa.

Fase 2Funcional mínimo
  1. Fallback de lista no ADD
  2. Títulos das listas no prompt (inclui compartilhadas)
  3. Respostas por template (sem naturalResponse)
  4. Reprompt, Help, Fallback, card LinkAccount
  5. One-shot encerra a sessão
Fase 3Experiência
  1. Vários itens por frase
  2. Desfazer real
  3. Leitura paginada + valores em reais
  4. Confirmação ao criar lista
Fase 4Publicação
  1. JSON do modelo no repo
  2. Unificar os 2 docs em 1
  3. Beta test com 2 ou 3 pessoas
  4. Submeter para certificação

6. Exemplo: como fica o handler depois

// 1. valida (assinatura, skill id), 2. auth + listas em paralelo
const [{ data: { user } }, { data: lists }] = await Promise.all([
  supabase.auth.getUser(),
  supabase.from('lists').select('id,title').is('deleted_at', null),
]);
// 3. LLM só interpreta (recebe os títulos exatos)
const intent = await parse(text, lists.map(l => l.title));
// 4. executa e fala o resultado REAL
const list = resolveList(intent.listName, lists, session.attributes.lastListId);
await addItems(list.id, intent.items);
return speak(`Anotei ${joinPt(intent.items)} no ${list.title}.`, {
  endSession: session.new,          // one-shot fecha
  reprompt: 'Quer anotar mais alguma coisa?',
  attrs: { lastListId: list.id, undo: { op: 'add', ids } },
});
